# 登录助手 / 站点备忘管理侧栏 — 设计方案

> 目标：在浏览器右侧侧栏集中展示**当前页匹配**的登录 Recipe 与站点备忘 Memo，并支持在侧栏内完成增删改查与一键执行；设置窗降级为「高级 / 互联」入口，日常管理不再依赖独立大窗。  
> 状态：**草案**（2026-07-27）  
> 前置：登录助手 V1、站点备忘 P1、通知收件箱侧栏壳（[companion-notification-inbox-sidebar-design.md](companion-notification-inbox-sidebar-design.md)）

## 0. 一句话结论

| 能力 | 结论 |
|------|------|
| 右侧侧栏展示当前 URL 匹配的 Recipe / Memo | **可行**。复用现有 `recipesMatchingURL:` / `memosMatchingURL:` |
| 侧栏内 CRUD | **可行**。数据面已齐；UI 从设置窗迁出/精简即可 |
| 侧栏内一键登录 / 填入备忘 | **可行**。直接调 `LoginAssistController` / Runner |
| 与通知侧栏并存 | **可行，但同槽互斥**。窗口右侧只保留一个侧栏槽，切换内容而非叠两个 |
| 另起工具栏图标 | **不建议（MVP）**。继续用钥匙菜单「管理…」+ 查看菜单；可选后续加独立按钮 |

**产品路径**：先做 **匹配列表 + 侧栏内编辑 + 执行**（LAS-MVP）；再做「全部配置」浏览、批量、草稿保存等增强（LAS-1）。

## 1. 方案定位

### 1.1 产品一句话

**站点助手侧栏**：打开后立刻看到「这一页能用什么登录配置 / 表单备忘」，并在侧栏里改完就能填——不必再在设置大窗与网页之间来回切。

### 1.2 要解决的痛点

| 场景 | 现状痛点 | 侧栏价值 |
|------|----------|----------|
| 到站后想确认「有没有配过」 | 只能看钥匙是否点亮或打开设置 | 一目了然列出匹配项 |
| 改一个 selector / 备忘字段 | 打开设置窗 → 分段 → 找条目 → 保存 → 回网页试 | 侧栏边看边改、立刻「填入」验证 |
| 同站多 Memo / 多账号 | 菜单层级深，管理分散 | 分组列表 + 内联默认标记 |
| 新建当前页备忘 | 设置里手填 host，易忘 path | 「为当前页新建」自动预填 host/path |

### 1.3 与现有能力的关系

| 能力 | 现状 | 本方案 |
|------|------|--------|
| 钥匙按钮 / ⌘⇧L / ⌘⇧M | ✅ 执行主路径 | **保留**；执行不必开侧栏 |
| 助手菜单「管理登录配置 / 管理站点备忘」 | ✅ 打开设置窗 | **改为优先打开侧栏**（设置仍可从侧栏「高级…」进入） |
| 设置窗「登录配置 \| 站点备忘」 | ✅ 完整 CRUD + 互联 | **保留**作高级编辑 / 互联 / 偏好；日常 CRUD 迁侧栏 |
| `LoginRecipeStore` / `FormMemoStore` | ✅ | **唯一数据源**；侧栏只消费 Store |
| 通知收件箱侧栏 | ✅ 右侧槽位 | **同槽互斥**：打开助手侧栏时关闭通知侧栏，反之亦然 |
| 登录内联钥匙 / Detector | ✅ | **不改** |

### 1.4 做什么 / 不做什么

| 做 | 不做 |
|----|------|
| 右侧 dock 侧栏；按当前 tab URL 列出匹配 Recipe + Memo | 第二个并列侧栏叠在通知旁 |
| 分段或分组：登录 / 备忘；支持「仅匹配 / 全部」 | 做成通用密码管理器库浏览产品 |
| 侧栏内新建、编辑、删除、设默认、点选选择器 | 侧栏内改 Companion / OTP 通道（仍走设置） |
| 行内「执行」（登录 / 填入）与结果反馈 | 进页自动填充；静默跑 Recipe |
| 查看菜单「站点助手侧栏」开关；钥匙菜单入口 | MVP 强制新工具栏图标（可选 LAS-1） |
| 宽度记忆、Esc 关闭、窄窗自动收起（对齐通知侧栏） | 云同步配置库 |

### 1.5 设计原则

1. **当前页优先**：默认只显示匹配当前 URL 的项；需要全局管理时切「全部」。  
2. **执行与管理同屏**：列表行可执行，详情区可编辑，改完无需离开侧栏验证。  
3. **数据面不变**：不合并 Recipe/Memo 类型；UI 统一，Store 仍平行。  
4. **同槽互斥**：右侧只开一个侧栏，避免双栏挤爆 WebView。  
5. **人在回路**：删除需确认；密码字段仍走 Keychain，侧栏不回显明文密码以外的安全倒退。  
6. **设置窗不删**：互联、偏好、复杂拾取失败时可退回大窗。

## 2. 用户体验

### 2.1 入口

| 入口 | 行为 |
|------|------|
| 钥匙菜单 →「管理登录配置…」/「管理站点备忘…」 | 打开侧栏并选中对应分段（登录 / 备忘）；若有匹配项可高亮第一条 |
| 文件菜单 →「登录助手…」/「站点备忘…」 | 同上（与现菜单文案可改为「站点助手侧栏…」或保留并打开侧栏） |
| 查看 →「站点助手」 | Toggle 侧栏（建议快捷键 **⌘⇧A**，Assist；若冲突再改） |
| 钥匙右键 / 助手菜单末尾「在侧栏中管理…」 | 打开侧栏，分段跟随当前页更有用的一侧（有 Memo 无 Recipe → 备忘） |
| （可选 LAS-1）ActionGroup 新按钮 | 与通知铃铛并列；角标 = 当前页匹配总数 |

**单击钥匙本身**：仍按现逻辑执行一键登录 / 填备忘 / 弹菜单，**不**改为仅打开侧栏（避免破坏肌肉记忆）。

### 2.2 布局（侧栏内部）

对齐通知侧栏壳（宽约 320～560，默认 360）：

```text
┌─ 站点助手 ─────────────── ✕ ─┐
│ [ 匹配当前页 ▾ ]  [ 全部 ]    │  ← 范围切换
│ [ 登录 | 备忘 | 全部类型 ]    │  ← 类型分段
│ 🔍 搜索标题 / host ……        │
├───────────────────────────────┤
│ ▼ 登录配置（2）               │
│   ★ Grafana · ops.example…   │  ← 行：标题、host、默认★、字段摘要
│     [一键登录] [仅填入]  …    │
│   云控制台备用账号            │
│ ▼ 站点备忘（1）               │
│   报障常用 · /tickets/new     │
│     [填入]                    │
├───────────────────────────────┤
│ 详情 / 编辑（选中项）          │
│  名称 / 主机 / 路径前缀        │
│  （登录）帐密·选择器…          │
│  （备忘）字段表 + 点选         │
│  [设为默认] [保存] [删除]      │
│  [为当前页新建登录] [新建备忘] │
└───────────────────────────────┘
```

| 区域 | 职责 |
|------|------|
| 顶栏 | 标题「站点助手」、关闭；可选「打开设置窗…」 |
| 范围 | **匹配当前页**（默认）/ **全部配置** |
| 类型分段 | 登录 / 备忘 / 全部（混合列表，section header 区分） |
| 搜索 | 过滤 title / host / pathPrefix（`SBTextField`） |
| 列表 | 匹配项卡片行；空态文案 +「为当前页新建」 |
| 详情 | 选中项就地编辑；未选中时显示空态或新建表单 |
| 底栏 | 新建快捷按钮；可选「高级设置…」 |

### 2.3 列表行信息架构

**登录 Recipe 行**

- 主标题：`title`（或 host）  
- 副标题：`host` + 可选 `pathPrefix`；模式徽章（密码 / 短信 / 混合）  
- 标记：默认 ★；自动登录 ⚡  
- 主操作：一键登录；次操作：仅填入 / 更多（设默认、删除、在设置中打开）

**站点备忘 Memo 行**

- 主标题：`title`  
- 副标题：`host` + `pathPrefix`；`N 个字段`  
- 标记：默认 ★  
- 主操作：填入；次操作：设默认、删除

风险域抑制时：列表仍可显示配置（便于管理），但「执行」按钮禁用并 tooltip「当前页为高风险域，请手动完成」。

### 2.4 空态

| 条件 | 文案 / CTA |
|------|------------|
| 匹配模式且无项 | 「当前页暂无登录配置或站点备忘」→「新建登录配置」「新建站点备忘」 |
| 全部模式且库空 | 「还没有任何配置」→ 同上 |
| 搜索无结果 | 「无匹配项」清除搜索 |

### 2.5 CRUD 行为

| 操作 | 行为 |
|------|------|
| **查** | 默认匹配列表；切「全部」+ 搜索 |
| **增** | 「为当前页新建」：预填 host（file→`file`）、建议 pathPrefix（文件名或 path）；进入详情编辑态；保存写入 Store |
| **改** | 详情区改字段 →「保存」；点选选择器复用 `LoginElementPicker`（侧栏 orderBack，拾取完回前） |
| **删** | 确认后 `deleteRecipe` / `deleteMemo`；Recipe 同步清 Keychain |
| **设默认** | 同 host 互斥，调用现有 `setDefault*` |
| **执行** | 调 `runRecipe:` / `runMemo:`；成功 toast；部分失败对话框可「定位到失败字段」 |

**密码字段**：侧栏详情用 `SBSecureTextField`；列表**永不**展示密码明文。备忘 value 可展示（本地明文产品语义已定），长文本折叠。

### 2.6 与设置窗分工

| 场景 | 用侧栏 | 用设置窗 |
|------|--------|----------|
| 日常看匹配、改 selector、改备忘字段、执行 | ✅ | — |
| Companion 配对 / 通知镜像 / 来电 / 同步 | — | ✅ |
| 内联助手开关、登录成功询问保存 | — | ✅（或侧栏「偏好」链过去） |
| 超长字段表、复杂并排对照 | 侧栏够用优先；不够再「在设置中打开」 | ✅ |

MVP 可不删除设置窗里的登录/备忘分区，避免双维护成本过高时采用：**侧栏为写路径，设置窗只读跳转或逐步瘦身**。推荐实现策略见 §5。

## 3. 与通知侧栏的槽位策略

当前窗口：

```text
contentRowStack
  ├── contentContainer（WebView）
  └── notificationSidebar
```

改造为**单槽多内容**：

```text
contentRowStack
  ├── contentContainer
  └── chromeSidebarHost
        ├── notificationSidebar.view   （互斥显示）
        └── siteAssistSidebar.view     （互斥显示）
```

| 策略 | 说明 |
|------|------|
| **推荐：单 Host + 互斥** | `BrowserChromeSidebarHost`（或 WindowController 内简单切换）同时只展示一种；打开 A 关闭 B |
| 宽度 | 两套可共用同一 `sidebarWidth` 记忆，或分 key（`MeoSiteAssistSidebarWidth`） |
| 动画 | 同通知：宽 0 ↔ 记忆宽，0.2s |
| 窄窗 | &lt; 720 自动关闭 |
| Esc | 关闭当前侧栏 |

不推荐两个侧栏同时打开：360×2 会严重挤压阅读区。

## 4. 架构

```text
BrowserWindowController
  └─ SiteAssistSidebarController（新）
        ├─ 观察 LoginRecipeStore / FormMemoStore / 当前 tab URL
        ├─ 列表：matched | all + filter
        ├─ 详情编辑 → upsert / delete
        └─ 执行 → LoginAssistController.runRecipe: / runMemo:

LoginAssistController
  └─ presentSiteAssistSidebarSelecting:（recipe|memo|auto）
        → window toggle + 分段

（可选）抽出 BrowserChromeSidebarHost
  └─ showNotification | showSiteAssist | hide
```

### 4.1 建议新增文件

| 文件 | 职责 |
|------|------|
| `LoginAssist/SiteAssistSidebar/SiteAssistSidebarController.h/.m` | 侧栏 UI + CRUD + 列表 |
| `LoginAssist/SiteAssistSidebar/SiteAssistSidebarSettings.h/.m` | 宽度等偏好 |
| （可选）`BrowserChromeSidebarHost.*` | 通知 / 助手互斥宿主 |

### 4.2 建议修改

| 文件 | 改动 |

### 4.3 复用

- 匹配与 Store API（零改数据模型）

## 5. 实现策略（减负双 UI）

完整两套编辑器（设置窗 + 侧栏）成本高。推荐：

| 阶段 | 策略 |
|------|------|
| **LAS-MVP** | 侧栏实现**完整**列表 + 详情 CRUD（从设置窗逻辑抽取/共享 helper）；设置窗登录/备忘分区保留但顶部提示「推荐使用侧栏管理」 |
| **LAS-1** | 抽取 `SiteAssistEditorView` 供侧栏与设置窗共用，去掉重复表单代码 |
| **LAS-2（可选）** | 设置窗移除登录/备忘大表单，仅留互联与全局偏好 +「打开侧栏」按钮 |

点选拾取、Keychain 读写逻辑必须单点实现，禁止复制两份。

## 6. 安全与隐私

1. Recipe 密码仅出现在侧栏详情的 Secure 字段；日志不打 value/password。  
2. Memo 明文提示保留：「勿存放密码」。  
3. 侧栏打开时不改变「清除网站数据不删配置」边界。  
4. 风险域：管理可看，执行遵循现有抑制。  
5. 多窗口：每窗侧栏状态独立；Store 进程级单例，改一处各窗列表刷新。

## 7. 分阶段交付

### LAS-MVP — 匹配列表 + 侧栏 CRUD + 执行

- 单槽互斥宿主（或最小：开助手关通知）  
- 匹配当前页列表（登录 + 备忘分组）  
- 详情编辑、保存、删除、设默认、为当前页新建  
- 行内执行；点选选择器  
- 入口：钥匙/文件「管理…」、查看菜单 Toggle  
- 宽度记忆、Esc、窄窗关闭  

**验收**

1. 打开测试页，侧栏仅显示匹配 Memo；填入成功。  
2. 侧栏新建登录配置并保存后，钥匙点亮且一键登录可用。  
3. 删备忘后列表与钥匙状态同步更新。  
4. 打开助手侧栏时通知侧栏关闭；再开通知则助手关闭。  
5. 输入控件符合 SBKit。

### LAS-1 — 体验增强

- 「全部配置」+ 搜索  
- 可选工具栏按钮 + 匹配数角标  
- 编辑器视图抽取共用  
- 失败字段在详情中高亮  
- ⌘⇧A 等快捷键定稿  

### LAS-2 — 收敛

- 设置窗瘦身；草稿保存进侧栏（衔接 FormMemo P2）  
- 可选：内联「在侧栏打开」从登录表单钥匙跳转  

### 明确不做（近期）

- 双栏同时打开  
- 云同步 / 团队共享配置库  
- 侧栏内完整 Companion 管理  
- 启发式自动发现普通表单并写入侧栏

## 8. 开放问题（待拍板）

1. **文件菜单「登录助手…」**：改为开侧栏，还是仍开设置窗、另增「站点助手侧栏」？建议：**管理类入口开侧栏**；设置窗改名为「登录助手与互联（高级）…」或保留并从侧栏进入。  
2. **快捷键 ⌘⇧A**：是否与现有冲突？无冲突则采用。  
3. **默认打开分段**：有匹配时优先「全部类型」混合，还是记住上次分段？建议：**记住每窗上次分段**，首次按「当前页更有内容的一侧」。  
4. **是否抽 `BrowserChromeSidebarHost`**：MVP 可在 WindowController 里 if/else 互斥；LAS-1 再抽。  
5. **设置窗登录/备忘表单**：MVP 保留还是立刻只读跳转？建议：**保留一版，减少风险**。

## 9. 可行性总评

| 项 | 可行性 | 说明 |
|----|--------|------|
| 匹配展示 | **高** | API 已有 |
| 侧栏壳 / 互斥 | **高** | 通知侧栏已验证布局 |
| 侧栏 CRUD | **高** | 设置窗已有交互可移植；注意宽度下的表单密度 |
| 执行闭环 | **高** | Controller 已暴露 run API |
| 双 UI 维护 | **中** | 用 §5 分阶段抽取降低 |

**结论**：适合作为登录助手 / 站点备忘的**日常管理面**；执行快捷键与钥匙行为保持不变；通知侧栏让出同槽即可，无需重做窗口骨架。
